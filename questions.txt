(2)
I avoided data races by giving each worker its own range of the file. Workers only read the shared input and search term, and each one writes to its own count or section of the results. After the workers finish, the main thread calls pthread_join on each one and then combines their results. Since no two workers write to the same result locations, I did not need a mutex. All four pthread tests passed.

(3)
OpenMP required less manual thread management than pthreads. Instead of creating threads, passing arguments, joining them, and merging results myself, I used pragma omp parallel and let OpenMP divide the loop iterations. For counting, I used a reduction so each thread keeps a private count and then the counts are combined at the end. For instances, I worked out where each line’s match belongs in the output array, so each thread writes to its own slots without overlapping with others. All four OpenMP tests passed. For timing, OpenMP took 0.025 seconds, compared with 0.032 by pthreads and 0.014 for serial. OpenMP was faster than pthreads in this run, but both parallel versions were slower than serial. Since these are single runs of a few hundredths of a second, I can’t say the 0.007-second difference between the two parallel versions is legitimately better.
